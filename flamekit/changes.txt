0.15.21 Nov 13, 2026
- A party window, pinned on the screen while you play (client): every player in the game, you first, each with their level, a green health bar and a blue mana bar with the exact numbers. Each player's name has its own colour and symbol, the same as on the minimap.
- Hold Right Alt while playing to get the mouse pointer: then the party window can be dragged by its title bar, made wider or narrower from its lower right corner, collapsed (–) or hidden (×). Let go of Right Alt to play on. Where it is and how it looks is kept for the next game.
- FlameKit's window (F6) has a Windows tab: show or hide each pinned window, or put it back in its first place. It also shows the log level key (Ctrl+Shift+F12) and where the logs are.
- The minimap marks other players with their own symbol and colour instead of a white dot.
- On a server without FlameKit: an orange line under the FlameKit label says some features are off; the party window then shows only you and your health, and says what is missing.

0.15.20 Nov 13, 2026
- Updates arrive without GitHub's cache delay: the updater first asks GitHub for the newest commit and then downloads the files at that exact commit (client). Before, GitHub could hand out an old update list for up to 5 minutes after a new version.
- The test channel checks for updates every minute; players' games still check every 10 minutes.
- A "Check for updates" button in FlameKit's window (F6) checks at once; the lower left corner then says "FlameKit is up to date" for a few seconds, or shows the green "ready" line.
- FlameKit's log: a repeated "up to date" check is a detail (full level only); failed checks are warnings.

0.15.19 Nov 13, 2026
- FlameKit's window (F6, client) has tabs: Auto Junk List, Minimap and Experimental. The Minimap and Experimental tabs have the same buttons as in the old panel and do the same things; any feature with a tab shows up there.
- Long tabs show in pages (< 1/2 >) instead of scrolling. Hovering a button shows its explanation.
- While FlameKit's window is open the mouse pointer shows over the whole game window, not only over FlameKit's window; a click outside FlameKit's window does nothing.
- FlameKit's windows use the game's own mouse pointer once the game has shown it (in the bag, the map or any menu); until then Windows' arrow.
- The client writes the tabs and the rows of the tab shown into ui_tabs.dat for FlameKit's window; clicks come back through ui_actions.txt.
- Tests: the tab bridge (rows written only while the tab is shown, a click does what the panel's button does, a click for rows no longer shown is dropped).

0.15.18 Nov 13, 2026
- FlameKit's log (client) no longer records other programs' window titles: a window that is not the game's is logged only by its program's file name (e.g. notepad.exe) and window class.
- FlameKit's log never contains the Windows user name: it is written as <user> (it appears in folder paths).

0.15.17 Nov 13, 2026
- A new version no longer changes anything in a running game: the updater downloads it, holds FlameKit's Lua part in emf\flamekit_update until the next game start and puts it in place then, so FlameKit's label keeps showing the version you are running until you restart (client).
- The update line in the lower left corner is green when an update is ready and says "Update v... is ready: restart the game"; red when an update failed, orange while downloading.

0.15.16 Nov 13, 2026
- FlameKit's UI (client) is drawn in one overlay window instead of three: the minimap, the Auto Junk List window (F6) and the lines in the lower left corner are layers of one picture. The picture is plain memory, so it can later be drawn inside the game's own frame (Vulkan) instead.
- The overlay counts as "in front" whenever any window of the game is the front window (it went missing after Alt+Tab), and Windows now tells FlameKit at once when the front window changes.
- A watchdog checks 4 times a second that the overlay is shown and in front of the game; every failure is logged with the window that was in the way, and repaired.
- FlameKit's own log (client): emf\mods\flamekit\logs\flamekit_<date>_<time>.log, one per game session, the newest 10 kept, up to 50 MB each. It has FlameKit's DLL, EMF's log (with the Lua part's lines), Windows and screen details, the game's memory and CPU use, the updater, the UI and the watchdog.
- Debug level in emf\mods\flamekit\debug.txt: off, normal (the default) or full; changes while the game runs. Ctrl+Shift+F12 in the game steps through the levels. Errors and warnings are always logged. The level shows in the lower left corner when it is not normal.
- The updater logs every check (up to date, failed and why), not only downloads.
- The Lua part (client and server) logs at the debug level too: clicks from FlameKit's window, the junk list going to the server half, files written for the DLL.
- A crash in one of FlameKit's own threads is logged with where it happened.
- Tests: the debug level is read from debug.txt, and off writes only warnings and errors.
